LogiFlow TMS backend

Transport Management System for road freight: clients and sites, fleet and drivers, orders, transport dossiers, voyage planning, maintenance, live tracking, and an AI façade.

This file is a map of the code so you can find the right place before you edit. Open it in a browser. Jump with the left menu.

1. Do this first (about 5 minutes)

  1. Need: JDK 24+ (CI uses 25), Docker Desktop, Git Bash or any bash.
  2. In the project root, copy env: cp .env.example .env
  3. Start Postgres + pgAdmin: make up

    or make run

Production (dev profile) requires a real Keycloak issuer.

2. What this app is

One Spring Boot JAR. Not microservices. Internally it is a modular monolith (Spring Modulith): each business area is a Java package with a locked public API.

The real-world flow the product models:

Client + Site→ Commande (order)→ Dossier transport→ Voyage (truck + driver)→ Events on the road

The frontend is a separate Angular 18 project. This repo is only the backend. Angular must never call the Flask AI service. Spring is the only public API.

Stack in one line:

  • Spring Web + Validation + Security (JWT resource server)
  • JPA / Hibernate Spatial + Flyway (schema owned by SQL, not Hibernate)
  • MapStruct (domain ↔ JPA entity), Lombok only on a short allow-list
  • springdoc OpenAPI, Actuator, Spring Modulith, ArchUnit tests

Hexagonal layers (inside every module)

Every module uses the same 4 folders. Dependencies only point inward. Tests in HexagonalArchitectureTest fail the build if you break this.

Layer Job You may put You must not put
api/ Public contract other modules may import Interfaces like SiteApi, records like SiteSummary JPA entities, REST DTOs, Spring controllers
domain/ Pure business. No Spring, JPA, Jackson, Lombok Entities, enums, value objects, ports (interfaces), domain services @Entity, @Service, REST, SQL
application/ Use cases. Owns @Transactional Services, *Command records, implements *Api HTTP, JPA, MapStruct. Never import infrastructure
infrastructure/ Adapters: REST + Postgres + HTTP clients Controllers, JPA entities, adapters, mappers Business rules (keep those in domain)

Typical file names (copy this pattern — referential is the template):

referential/
  api/SiteApi.java                          ← other modules call only this
  api/dto/SiteSummary.java
  domain/model/Site.java                    ← Site.creer() / modifier() / desactiver()
  domain/port/out/SiteRepository.java          ← interface, no Spring
  domain/service/SiteDomainService.java
  application/SiteService.java               ← @Transactional, implements SiteApi
  application/command/CreerSiteCommand.java
  infrastructure/web/SiteController.java    ← /api/v1/sites
  infrastructure/web/dto/SiteRequest.java   ← REST in
  infrastructure/web/dto/SiteResponse.java    ← REST out
  infrastructure/persistence/entity/SiteEntity.java
  infrastructure/persistence/repository/SiteJpaRepository.java
  infrastructure/persistence/adapter/SiteRepositoryAdapter.java
  infrastructure/persistence/mapper/SiteMapper.java   ← MapStruct

Domain entities always have two factories:

  • creer(...) — new object, applies creation rules
  • reconstituer(...) — rebuild from DB, skip creation rules

JPA *Entity never leaves persistence. Controllers never return domain objects to HTTP — they map to *Response.

One request, end to end (edit this mental model)

Example: POST /api/v1/sites

  1. SiteController.creer validates SiteRequest (Bean Validation).
  2. Maps it to CreerSiteCommand (application command, not HTTP).
  3. SiteService.creerSite (@Transactional) asks SiteDomainService if the code is free, then Site.creer(...).
  4. SiteRepository is a domain port. The real class is SiteRepositoryAdapter: MapStruct → SiteEntity → JPA save.
  5. Controller loads the site again and returns SiteResponse with HTTP 201 + Location.
  6. If something throws, GlobalExceptionHandler turns it into RFC 7807 JSON: 404, 409, 422, 400, 503, 500 — never a raw stack trace.
To change “what a site is” edit Site.java. To change “how we save it” edit adapter + mapper + SQL. To change “the JSON the frontend sends” edit SiteRequest / SiteResponse.

Module shared — technical kernel

OPEN module. Other modules import it freely. No business of its own.

  • Value objects: GeoPoint, Money, Reference, Capacite
  • Exceptions: BusinessException (422), NotFoundException (404), ConflictException (409), ValidationException (400), ServiceIndisponibleException (503)
  • GlobalExceptionHandler + i18n messages_fr.properties / messages_en.properties
  • BaseEntity: UUID id, audit columns, optimistic lock version
  • Pagination types, security context helper
Edit here when: you need a new shared VO, a new error type, or a change to error JSON. Do not put “voyage” or “camion” rules here.

Module order — commercial orders

Commande: a customer’s request to move goods. Status: RECUE → CONFIRMEE / ANNULEE.

Has a Reference (human-readable code) from SequenceReferenceGenerator.

HTTPDoes
POST /api/v1/commandesCreate (status RECUE)
GET /api/v1/commandesGet / list

A commande is not a truck trip. After confirmation, you create DossierTransport records from it.

Module dossier — transport files

DossierTransport is the billable, movable unit: goods lines, segments (load → unload), documents, weight / volume / pallets, ADR (dangerous goods), required body type and temperature.

Status machine:

CREE → PLANIFIE → EN_CHARGEMENT → CHARGE → EN_TRANSIT → EN_LIVRAISON → LIVRE → CLOTURE
                      ↘ ANNULE                    ↘ INCIDENT ↩ EN_TRANSIT
PLANIFIE can go back to CREE
HTTPDoes
POST /api/v1/dossiersCreate from a commande
GET /api/v1/dossiersGet / list
PUT /api/v1/dossiers/{id}/statutAdvance / change status

Hard grouping rules live in DossierTransport.estGroupableAvec: both must be groupable, same TypeTransport, compatible body type and temperature. Geography, schedules and resources are not here — that is the AI planning agent + planning.

Change grouping compatibility → estGroupableAvec + DossierTransportTest. The AI module must not import this class; it reads DossierApi summaries (candidatsPlanification) instead.

Module planning — voyages

Voyage = one physical run: vehicle + optional trailer + driver assignment(s) carrying 1..n dossiers. Also holds Trajet (ordered steps) and fill rate.

Status: BROUILLON → PLANIFIE → AFFECTE → EN_COURS → TERMINE → CLOTURE (or ANNULE from early states).

ConformiteVoyageService (application) gathers every rule, with ConformiteDomainService for the pure checks: resources free over the period (other voyages and workshop work orders via MaintenanceApi.indisponibilites), documents valid on departure, tractor ⇒ trailer, body type and temperature, capacity per leg, licences / ADR / passport, driving balance of the crew. Stops (ArretVoyage) are persisted at creation.

HTTPDoes
POST /api/v1/voyagesCreate (stops + compliance check)
GET /api/v1/voyagesGet / list
PUT /api/v1/voyages/{id}/statutTransition
POST /api/v1/voyages/conformiteDry-run compliance check
GET /api/v1/voyages/ressources-disponiblesFree vehicles / trailers / drivers over a period
GET /api/v1/voyages/{id}/capacite, …/arrets, POST …/dossiersCapacity per leg, stops, add a dossier

The AI planning agent proposes complete voyages; Spring re-validates each one with the same rules (VoyageApi.evaluerConformite).

Voyage rows store some nested structures as JSON text (trajet_json, affectations_json, dossier_ids_json) — see V12.

Illegal status jump? Map is in Voyage.java field TRANSITIONS_AUTORISEES. Change the map, then tests in VoyageTest.

Module maintenance — workshop, claims, insurance, costs

Covers vehicles and trailers (EnginRef(type, id)). Aggregates:

  • OrdreTravail — work order: type, nature, priority, origin (manual, plan, claim, AI agent), supplier, cost lines with VAT, workflow PLANIFIE → EN_COURS ⇄ EN_ATTENTE_PIECES → TERMINE (only via closure: end date, meter reading, ≥ 1 cost line) or ANNULE
  • PlanEntretien — periodicity (km / months / hours), last completion, computed next due date (OK / ALERTE / ECHU)
  • Sinistre — claim: circumstances, third party, insurance follow-up, repairs, net cost
  • Prestataire, ContratAssurance — suppliers and insurance policies
  • ScoreSante — health score written by the predictive AI agent

Module ai — façade, not the models

No LLM code here. For each agent, Spring authenticates the user, builds the context from other modules’ APIs, calls Flask with header X-Internal-Api-Key, validates or stores the result, logs InteractionIa and returns ready-made JSON (or an SSE stream) to Angular.

Frontend (Spring)Flask (internal)If Flask is down
/api/v1/ia/copilote/** (conversations, SSE messages)/internal/ai/v1/copilot/**erreur event
POST /api/v1/ia/planification/propositions/internal/ai/v1/planification/proposer503 → manual planning
POST /api/v1/ia/maintenance/analyse/internal/ai/v1/maintenance/recommander503; automatic runs are just logged
POST /api/v1/ia/itineraires/calcul/internal/ai/v1/itinerary/calculer503

Copilot tools: Flask calls back /internal/copilote/outils/** with a separate callback key and a per-message context token, so tools always run with the real user’s roles. Tools are classes implementing OutilCopilote in ai/application/outils.

Predictive maintenance also runs by itself: every night (AnalyseMaintenanceNocturne, 5 am Paris) and after domain events (ReanalyseMaintenanceListener).

Contract change? Update the records in ai/domain/model/** and the Pydantic schemas in the Flask repo. New copilot tool? Add an OutilCopilote class — Flask discovers it. URLs / keys: AI_SERVICE_*, AI_MAINTENANCE_*.

How to add or change an API (recipe)

Example: add a field commentaire on a site.

  1. SQL: new file src/main/resources/db/migration/V17__site_commentaire.sql — ALTER TABLE referential.site ADD COLUMN …
  2. Domain: field + validation on Site.java (creer / modifier / reconstituer)
  3. JPA: column on SiteEntity
  4. MapStruct: SiteMapper (often automatic if names match)
  5. Command: CreerSiteCommand / MajSiteCommand
  6. REST: SiteRequest + SiteResponse
  7. If other modules need it: SiteSummary + SiteApi
  8. Tests: SiteTest (domain) and/or SiteControllerIT
  9. make format then ./mvnw test

Controller rules (enforced by convention + ArchUnit):

  • No business logic. Validate DTO → call application service → map response.
  • Constructor injection only (Lombok @RequiredArgsConstructor is allowed).
  • Path style: /api/v1/<resource> in French kebab-case matching existing APIs.

How to change a business rule

  1. Find the domain class (e.g. Voyage.java, DossierTransport.java).
  2. Change the method or the transition map. Throw BusinessException for “user did something illegal”.
  3. Add/adjust a test next to it: src/test/java/.../domain/*Test.java — no Spring needed.
  4. If the rule needs data from another module, go through that module’s *Api, from the application layer.
Do not put the rule in the controller or in a JPA entity. Domain coverage is measured by JaCoCo (target 80% on *.domain.*).

How to change the database

  1. Never edit an already-applied V1…Vn on a shared DB. Add V(n+1)__description.sql.
  2. Tables: snake_case singular. PK id. FKs <table>_id. Named constraints: pk_ fk_ uq_ idx_ ck_.
  3. Local wipe (destroys data): make db-reset then restart the app so Flyway replays everything including seed.
  4. Hibernate only validates. If you add a Java field without a column, startup fails.

Every persisted row also has tenant_id, audit, and version from BaseEntity.

Config, security, profiles

Files

  • application.yml — port 8080, Flyway, Jackson, Actuator, AI defaults, CORS
  • application-local.yml — DB on 5433, seed migrations, permissive security, DEBUG logs
  • application-dev.yml — real OAuth2 issuer, no permissive mode
  • application-test.yml — tests / Testcontainers

Security

  • Stateless, CSRF off, CORS from CORS_ALLOWED_ORIGINS
  • Public: health, info, swagger, api-docs
  • Everything else: authenticated
  • JWT roles from claim roles or Keycloak realm_access.roles → ROLE_*

App-level properties: prefix logiflow.* in LogiflowProperties (CORS + permissive flag). AI has its own AiServiceProperties.

Cross-cutting Spring beans live in com.logiflow.tms.config, not inside a business module:

  • SecurityConfig, CorsConfig, JpaConfig, OpenApiConfig, JacksonConfig, AsyncConfig

Rules that will break the build if you ignore them

  1. Domain stays pure. No Spring/JPA/Jackson/Lombok in *.domain.*.
  2. Application never imports infrastructure.
  3. Other modules only import ….api (except open shared).
  4. No cycles between modules (e.g. dossier must not import planning).
  5. Spotless must pass — run make format before you push.
  6. Lombok allow-list: @RequiredArgsConstructor, @Getter, @Slf4j, @Builder. Forbidden: @Data, @Setter on entities, @AllArgsConstructor on JPA entities.
  7. Language: technical names in English; business terms that the team kept in French stay French everywhere (Voyage, DossierTransport, Horaires…). Comments and user-facing errors in French.
  8. Records for DTOs, commands, VOs. Collections returned immutable.
  9. Optional only as a return type, never a field or parameter.
